# Contributing to the review draft

Please identify the version, numbered section, and page when reporting feedback.
For a conceptual correction, quote the short claim at issue, explain the problem,
and provide a primary source or minimal counterexample. For confusing teaching,
say what you knew before the passage and which new term or transition lost you.

For code, use the unchanged baseline first. Supply the exact query, input change,
engine/library version, expected result, actual result, and a small reproducer.
Keep intentional model extensions separate from baseline fixtures. Never upload
private learner records, credentials, or proprietary source material.

A proposed change should preserve the running example's IDs, units, and declared
policy unless the model change is intentional and documented. Rerun the affected
checks. Technical review should distinguish entailment, validation, write-time
constraints, application decisions, and product-specific behavior.

If changing an illustration, check arrow direction against the accompanying
sentence and add meaningful alternate text. If changing prose, introduce the
need before a new technology name and say what every example is meant to show.

Corrections, questions, and proposed improvements are welcome through issues and
pull requests. Original book text, diagrams, and synthetic data use CC BY 4.0;
original code uses MIT. Submit only material you have the right to contribute,
and identify third-party material and its license. Contributions to each scope
are made under that scope's existing license; see LICENSE.md.
